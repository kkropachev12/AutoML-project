# План выполнения итогового проекта AutoML

## Тема проекта

AutoML-пайплайн для прогнозирования оттока клиентов телеком-компании.

## Датасет

Для проекта используется готовый датасет Telco Customer Churn.

Целевая переменная: `Churn`.

Задача: бинарная классификация, клиент уйдет или останется.

## Бизнес-задача

Телеком-компания хочет заранее находить клиентов с высоким риском оттока. Это позволит предложить удерживающие акции, скидки или персональные предложения до того, как клиент уйдет.

## ML-задача

Построить AutoML-пайплайн бинарной классификации, который по данным клиента прогнозирует вероятность оттока.

## Этап 1. Подготовка проекта

1. Создать структуру репозитория.
2. Добавить базовые файлы проекта.
3. Описать тему, цель, бизнес-задачу и ML-задачу.
4. Подготовить место для кода, тестов, данных, моделей, графиков и отчета.

## Этап 2. Загрузка данных и ETL

1. Загрузить готовый CSV Telco Customer Churn.
2. Очистить колонку `TotalCharges`.
3. Обработать пропущенные значения.
4. Разделить признаки и целевую переменную `Churn`.
5. Описать этапы ETL:
   - Extract: загрузка CSV;
   - Transform: очистка данных и подготовка признаков;
   - Load: сохранение обработанных данных и артефактов.

## Этап 3. Baseline-модель

1. Собрать первый ML-пайплайн.
2. Добавить обработку числовых и категориальных признаков.
3. Обучить baseline-модель `LogisticRegression`.
4. Посчитать основные метрики.
5. Сохранить модель и результаты.

## Этап 4. Визуализации

1. Построить распределение целевой переменной `Churn`.
2. Построить распределение `MonthlyCharges` по классам `Churn`.
3. Построить confusion matrix.
4. Построить ROC curve.
5. Сохранить графики для отчета и презентации.

## Этап 5. AutoML

1. Реализовать простой кастомный AutoML через Optuna.
2. Добавить модели-кандидаты:
   - `LogisticRegression`;
   - `RandomForestClassifier`;
   - `GradientBoostingClassifier`.
3. Настроить подбор гиперпараметров.
4. Выбирать лучшую модель по ROC-AUC.
5. Сохранить лучшую модель, параметры и метрики.

## Этап 6. Оценка модели

1. Посчитать финальные метрики:
   - Accuracy;
   - Precision;
   - Recall;
   - F1-score;
   - ROC-AUC.
2. Сравнить baseline-модель и AutoML-модель.
3. Добавить feature importance или permutation importance.
4. Сделать выводы по качеству модели.

## Этап 7. Мониторинг

1. Добавить MLflow для логирования экспериментов.
2. Логировать параметры моделей, метрики и артефакты.
3. Добавить мониторинг ресурсов через `psutil`.
4. Сохранять время обучения, CPU и RAM в `resource_usage.json`.

## Этап 8. Тестирование

1. Добавить тесты через `pytest`.
2. Проверить загрузку и очистку данных.
3. Проверить создание ML-пайплайна.
4. Проверить обучение модели.
5. Проверить запуск AutoML на малом числе итераций.
6. Проверить создание основных артефактов.

## Этап 9. Docker

1. Создать `Dockerfile`.
2. Добавить `.dockerignore`.
3. Настроить установку зависимостей.
4. Настроить запуск обучения внутри контейнера.
5. Описать команды сборки и запуска.

## Этап 10. CI/CD

1. Настроить GitHub Actions.
2. Запускать тесты при push и pull request.
3. Запускать короткий smoke-test обучения.
4. Проверять сборку Docker-образа.

## Этап 11. Итоговый отчет

1. Оформить README как итоговый отчет.
2. Добавить описание бизнес-задачи.
3. Добавить описание датасета.
4. Добавить описание ETL и ML-пайплайна.
5. Добавить результаты модели, графики и выводы.
6. Добавить описание тестирования, Docker, CI/CD и мониторинга.

## Этап 12. Презентация

1. Подготовить презентацию на 5-7 слайдов.
2. Включить бизнес-задачу, датасет и архитектуру пайплайна.
3. Показать AutoML-подход и результаты.
4. Добавить информацию про Docker, CI/CD и мониторинг.
5. Сформулировать выводы для бизнеса.

## Git workflow

1. Основная ветка проекта: `main`.
2. Рабочая ветка проекта: `develop`.
3. Разработка ведется в `develop`.
4. Каждый этап фиксируется отдельным коммитом.
5. После завершения проекта финальная версия сливается в `main`.
